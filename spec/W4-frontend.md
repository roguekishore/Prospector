# W4 — Frontend

**Read `MASTER.md` first.** This spec owns everything the operator looks at.

**Owns:** `preview/` — `index.html`, `app.css`, `app.js`, `mocks.js`
**Reads:** `data/index.json` (`MASTER.md §4.7`) and the PNGs under `data/`
**Writes:** operator marks, via the review API (`W3 §10`) or `localStorage`
**Blocked by:** nothing. A working implementation already exists in `preview/`,
and 18 fixture leads are on disk.

---

## 0. Start from what exists — do not rebuild

`preview/` already contains a **working, approved** implementation of every view
in this spec. Your job is to wire it to real data and finish the gaps in §10, not
to start over.

`preview/app.css` is the **design contract, copied forward byte-for-byte.** It is
not a reference to reinterpret. §2 restates its tokens literally so an agent that
never opens the file still lands in the same place — if the two ever disagree,
**the CSS file wins.**

---

## 1. Why the interface looks like this

One rule explains every other decision: **the screenshots are the only colour in
the interface.** Every coloured pixel in the operator's field of view belongs to a
lead, not to the chrome. That is what makes reviewing 200 sites in fifteen
minutes tolerable rather than exhausting.

Consequences, all non-negotiable:

- No accent colour. No brand colour. No coloured tier badge. No chart palette.
- Tier is a **glyph**, never a hue: `■ A · ▣ B · □ C · · X`.
- Hierarchy comes from four opacity steps and hairline rules, nothing else.
- Emphasis is an **inverted block** (white ground, black ink), not a colour.

If a future feature seems to need colour, it does not. Use weight, opacity,
inversion, or space.

---

## 2. Design tokens — restated verbatim from `app.css`

```css
--ink: #fff;                          /* the only ink colour            */
--bg:  #000;                          /* pure black, not #0a0a0a        */
--o1: 1;    --o2: .64;  --o3: .40;  --o4: .24;    /* the four steps     */
--rule:        rgba(255,255,255,.12);
--rule-strong: rgba(255,255,255,.22);
--mono: ui-monospace,"SF Mono",SFMono-Regular,"Cascadia Mono",
        "JetBrains Mono",Menlo,Consolas,"Liberation Mono",monospace;
--t: 120ms;                           /* the only transition duration   */
--u: 8px;                             /* spacing unit; all gaps are × u */
```

Type scale, in px, exhaustive:

| class | size | tracking | use |
|---|---|---|---|
| `.t-micro` | 10 | `.14em` upper | labels, keycaps, nav |
| `.t-small` | 11 | `.04em` | secondary rows, notes |
| `.t-body` | 13 | — | body default |
| `.t-lg` | 17 | `-.01em` | view titles |
| `.t-xl` | 26 | `-.02em` | stat figures |
| `.t-num` | 34 | `-.03em` | hero counts |

One monospace family throughout. No shadows. No rounded corners. No animation
beyond the 120ms crossfade. All numeric columns get
`font-variant-numeric: tabular-nums` so figures align down a column.

## 3. Data source

`index.json` (`MASTER.md §4.7`) is the **only** data file. One fetch, no per-lead
requests.

```js
// production: generated by `report`
const res = await fetch('../data/index.json', {cache: 'no-store'});
// development fallback: the synthetic fixture already on disk
//   preview/data.js defines VERTICALS / LEADS / AGENCIES as globals
```

Resolution order, implemented once at boot:

1. `GET /api/index.json` — the review API is serving (`W3 §10`).
2. `../data/index.json` — a real run exists on disk.
3. The globals from `data.js` — synthetic fixture, dev only.

**When the loaded data has `synthetic: true`, or came from source 3, render a
permanent marker in the topbar** reading `SYNTHETIC FIXTURE — NOT REAL LEADS`, in
an inverted block. `MASTER.md §10`: those 18 businesses have invented phone
numbers, invented addresses, and invented agency pricing. Nobody must ever pitch
from them or quote one of those prices.

## 4. Views

Six, routed by in-memory state (no URL routing needed, no history API).

```
home       vertical cards, stat strip, LLM-free agreement figure
grid       lead thumbnails for one vertical, filterable
deck       the review deck — where the operator actually lives
agencies   who built these sites, what they charge, expansion counts
pitch      what the operator marked, outreach-ready, CSV export
disagree   machine tier ≠ operator tier — audits the scoring weights
```

### 4.1 home

Stat strip across the top: `discovered · audited · scored · tier A · marked ·
agreement`. Then one card per vertical: label, city, keyword count, a four-segment
tier bar, counts for hot/warm/weak/skip, and `n/m reviewed`.

The agreement figure is `matching / reviewed` across all leads where the operator
has set a tier. It is the honest measure of whether the weights match the
operator's taste — and the input to retuning (`MASTER.md §5.4`).

### 4.2 grid

Filter chips: `all · A · B · C · X · unreviewed · marked`, each with a live count.
Thumbnails are the **mobile** capture, cropped to fill width, with the tier glyph
and score in an inverted badge at top-left and a `⚑` at top-right when marked.
A reviewed card is overlaid with a 45° hatch so the eye skips it.

Below each: domain, business name, and the pitch angle clamped to two lines.

### 4.3 deck — the important one

Three columns, exact widths from `app.css`:

```
270px              minmax(0,1fr)            300px
┌────────────────┬────────────────────────┬──────────────────┐
│ identity       │                        │ MACHINE VERDICT  │
│ ★ rating       │   the capture          │  tier + score    │
│                │                        │  reasons (≤5)    │
│ SIGNALS        │   full bleed,          │                  │
│  copyright 2019│   contain-fit          │ PITCH ANGLE      │
│  jquery  1.12  │                        │  (inverted box)  │
│  viewport   ✗  │   mobile default       │                  │
│  overflow +142 │                        │ YOUR CALL        │
│  lcp      8.4s │                        │  ■A ▣B □C ·X     │
│                │                        │  mark for pitch  │
│ LINKS          │                        │  note…           │
│ CONTACTS       │                        │  agrees / over-  │
│ BUILT BY       │                        │  rides machine   │
└────────────────┴────────────────────────┴──────────────────┘
  ←→ move · 1234 tier · P pitch · N note · MDF shot · O open · U next · Esc grid
```

**Mobile is the default capture**, because these businesses get most of their
traffic on phones and a no-viewport-meta site visibly breaks at 390px. That
screenshot *is* the pitch.

A flagged signal row renders **inverted** (white ground, black text) — that is how
the operator sees at a glance which facts the machine is reasoning from. Order
rows worst-first, matching `flagged` order from W3.

The left rail shows the evidence, the right rail shows the conclusion. That
adjacency is deliberate: it lets the operator catch an over- or under-call
immediately, which is the entire purpose of the Disagreements view.

`P` marks for pitch **independently of tier**, because sometimes a C-tier site
has one glaring flaw the operator knows how to sell.

### 4.4 agencies

Table: agency name and domain, sites built in this run (as chips), portfolio
client count, published pricing tiers, and a note. Published pricing is the local
price floor — it tells the operator both what these clients already accept and
where to position above it.

### 4.5 pitch

Every marked lead, sorted by score: domain, business, rating, machine tier,
operator tier, angle, phone, email, note. One `Export CSV` button.

When the review API is available, `POST /api/export/pitch` and report the written
path. Otherwise build the CSV client-side with a BOM and trigger a download.

### 4.6 disagree

Rows where operator tier ≠ machine tier, with the direction (`rated up` /
`rated down`), the machine's first reason, and the operator's note. Plus the
agreement percentage.

This view is the feedback loop: it tells you which weight to move in
`lib-scoring.js` (`MASTER.md §5.4`), and it is why `scores` and `reviews` are
separate tables.

## 5. Keybindings — FROZEN

Active in the deck only. Ignored while a textarea has focus, except `Esc`, which
blurs.

| key | action |
|---|---|
| `←` / `→`, `k` / `j` | previous / next lead |
| `1` `2` `3` `4` | set tier A / B / C / X (pressing the current tier clears it) |
| `P` | toggle mark for pitch |
| `N` | focus the note field |
| `M` / `D` / `F` | mobile / desktop / full capture |
| `O` | open the real site in a new tab |
| `U` | jump to the next unreviewed lead |
| `Esc` | back to grid |

Every binding is also a visible, clickable control. Keyboard is the fast path,
never the only path.

## 6. Stage painting — real PNG first, always

One function paints every capture surface, in the grid and in the deck.

```js
// probe the real capture, fall back to the CSS rebuild
data/<vertical>/<domain>/<shot>.png   →  <img>            (preferred)
renderMock(lead, shot, w, h, mode)    →  CSS recreation   (fallback only)
```

Probe with `new Image()` and cache the promise per `domain/shot` so a repaint
never re-probes. **Guard against a stale paint:** the box may have been repainted
for a different lead or shot while the probe was in flight, so re-check
`box.dataset` before writing into it.

Two fit modes: `contain` (whole frame visible — the deck) and `cover` (fill
width, crop the bottom — grid thumbnails).

`mocks.js` exists only because the original screenshots had been cleared from
cache before they could be read. **Delete it once real captures exist**
(`MASTER.md §10`) — the probe already prefers the real PNG, so removal is a
one-line change in the fallback branch.

### 6.1 The mock's one honest trick

When `signals.viewport === "missing"`, the mobile mock renders the 980px legacy
layout squeezed into a 390px frame, because that is what a browser actually does
with a page that declares no viewport. It is the single most sellable fact the
interface shows. Preserve that behaviour for as long as `mocks.js` survives.

## 7. Persistence

```js
PUT /api/review/:domain  {human_tier, pitch, note}      // when serving
localStorage['prospector.reviews.v1']                    // always, as cache
```

Write to `localStorage` **synchronously on every change** and fire the `PUT`
opportunistically. If the `PUT` fails, keep the local value and show nothing —
the operator must never lose a mark to a network error, and must never be
interrupted by a toast about one.

Wrap every `localStorage` access in `try/catch`. Private mode and some preview
contexts throw on access, and the deck must still render correctly with no stored
value.

Seed from `index.json`'s own values on first run, then let local state win.

---

## 8. Performance

- **Preload the next three leads' captures** on every deck advance. This is what
  makes 200 leads take fifteen minutes instead of forty.
- Never hold more than ~12 decoded full-page PNGs; drop `src` on cards scrolled
  far out of view if memory becomes a problem at 500 leads.
- Repaint on resize is debounced 120ms.
- `index.json` is fetched once and held in memory. No refetch on navigation.

---

## 9. Accessibility

Not optional, and cheap here.

- Every interactive element is a real `<button>` or `<a href>`, never a
  `div` with a click handler.
- `:focus-visible` is a 1px white outline at 2px offset — already in `app.css`.
  Never remove focus styling.
- Filter chips and tier buttons use `aria-pressed`. Nav links use
  `aria-current="page"`.
- Every capture `<img>` gets a real alt: `"<domain> mobile capture"`.
- The keycap footer is the visible keyboard documentation.
- `@media (prefers-reduced-motion: reduce)` disables the crossfade — already in
  `app.css`.
- Contrast: the `--o4` step (.24) is decorative only. **Never** put text the
  operator needs to read at `--o4` on black.

## 10. What is genuinely missing from the existing implementation

Everything else in `preview/` works. These are the gaps:

1. **`index.json` loading** with the three-source resolution order in §3. The
   current build reads `data.js` globals only.
2. **The synthetic banner.** Nothing currently marks fixture data as fake, which
   is the one defect that could cause real harm — an invented phone number or an
   invented agency price presented as fact.
3. **Review API calls.** Persistence is `localStorage`-only today.
4. **Server-side pitch export.** Currently client-side only.
5. **Agency pricing** is read from the fixture; wire it to `index.json.agencies`.
6. **Empty and error states.** A run with zero leads, a missing `index.json`, and
   a lead whose captures all failed (`error.json` present) each need a plain
   one-line state, not a blank screen.

## 11. Acceptance criteria

1. Loads and renders from a real `index.json` with no `data.js` present.
2. Falls back to `data.js` when no `index.json` exists, and shows the synthetic
   banner in that case.
3. Shows the synthetic banner whenever `index.json.synthetic === true`.
4. Real PNGs are used when present; the CSS rebuild appears only when they are
   absent.
5. Every keybinding in §5 works, and each has a visible clickable equivalent.
6. Marking a lead under the `unreviewed` filter does not jump the deck to a
   different lead — position re-anchors on the domain, not the index.
7. Marks survive a reload with the API unavailable, and sync when it returns.
8. A 500-lead `index.json` reaches interactive in under 1.5s on this machine.
9. Nothing renders in any colour other than black, white, or an opacity step of
   white — verified by grepping the CSS for hex values other than `#fff`/`#000`
   and `rgba(255,255,255,*)`.
10. Deck, grid, and tables are usable at 1280px wide; rails collapse below 860px
    and no view scrolls horizontally.
11. `localStorage` throwing does not prevent the deck from rendering.

## 12. Do not

- Do not introduce React, Vue, Svelte, Tailwind, shadcn, or a bundler. Plain
  HTML/CSS/JS, no build step. This is a single-user local tool; a toolchain is
  pure cost here.
- Do not add a colour. Not for tiers, not for charts, not for status.
- Do not rewrite `app.css`. Extend it in the same idiom.
- Do not fetch per-lead JSON. `index.json` holds everything.
- Do not add auth, telemetry, or an external font/CDN request. The interface runs
  offline; Google Fonts is a network dependency and is not used.
- Do not compute or re-derive a tier, score, or angle in the frontend. Those come
  from `score.json` via `index.json`. The frontend renders judgements and records
  the operator's; it never makes one.
